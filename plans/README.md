### Two orthogonal axes of the "Codegen-facing derivations" problem

- **Backend leakage (003–008, DONE):** the derivations *emitted C++/KDL strings*.
  Fixed by moving rendering into the `.stg` templates; ir_gen now emits structured IR.
- **Post-pass architecture (009, TODO):** the derivations *run as a second pass over
  the assembled `ir` dict* (`derive_codegen_fields(ir)`). The IR is ir_gen's final
  artifact — nothing should re-read and re-process it. 009 folds every one of the 16
  operations into the construction of its piece (scene/solvers/closures/motions/
  introspection) so `generate_ir` is a single forward pass. Stronger gate than
  003–008: `ir.json` must be **byte-identical** (only computation *location* moves),
  so `frame_layout.h` hashes stay unchanged too.

**Refactor complete (003–008).** `ir_gen.py`'s "Codegen-facing derivations" section
emits only backend-agnostic structured IR; the sole `KDL::` left is one pre-existing
comment at ir_gen.py:1324 (outside the section, RDF-parsing area). Generated C++ is
byte-identical across all 8 buildable models (the only delta is the `frame_layout.h`
schema-hash version markers — see the deviation note under batch 003–005; the wire
contract is unchanged). 27 pytest pass. FSM gate calls (008) verified via
pick_place_single/rnea/wait (8 calls each, byte-identical in ref_main.cpp).

**Two ST4 gotchas found & worked around (for future template work):**
- A JSON empty list `[]` is **truthy** in this STSTv4 build (`<if(list)>` and
  `<if(first(list))>` are both true when empty; only `<if(rest(list))>` is false).
  Empty-vs-nonempty must be gated by an explicit Python boolean flag (e.g.
  `when_terms_present`), never by testing the list itself.
- A string **literal** passed as a template argument (`foo(x, "true")`) renders
  empty. Pass such defaults as inline `<else>literal<endif>` at the call site, not
  as an argument.
- The golden diff **must** include `headers/<motion>.hpp` (per-motion signatures +
  can_start body live there) — checking only `ref_main.cpp` misses signature/condition
  regressions. The helper now diffs all generated `.cpp/.hpp/.h` recursively.

**One deviation from strict byte-identity:** `frame_layout.h`'s two version
markers `kSchemaHash` / `kFrameLayoutHash` change. They are `sha256` over the
*entire* schema JSON, which now stores backend-agnostic descriptors/ids instead
of baked C++ expr strings. The observable **wire contract** (field names, numbers,
offsets, types) is provably unchanged (verified: only the 2 hash lines differ per
model). The hash shift is unavoidable — the old hash baked the very expr strings
this refactor removes. Follow-up option: narrow the hash to the wire contract so
it is stable against future representation refactors (separate concern; not done).

## Key facts (established during the audit, shared by all six plans)

- The template backend **already** has `access-expr(id, views)`
  (`code-generator/shared_data.stg:128`) that renders C++/KDL access from an
  abstract signal id + the `views` map — an exact mirror of the Python
  `cpp_access_expr` (the template version is more complete: it also handles
  `PoseDifference`). The Python versions are duplicates to delete.
- There are **two** C++-baking Python layers: `ir_gen.py` (the target) and
  `codegen_artifacts.py` (build-side, sees `ir.json`+`fsm_ir.json`). Several
  introspection exprs are split across both (`sample_expr`↔`expr`, `_shared_expr`,
  `active_condition` reuse). Plans 003/005/006 touch both — read their scope.
- Example model set (golden diff, all in `src/bdd_collab_bhv_cpp/models/`): the
  **8 that generate** — `admittance_arc_single` + `robmot-examples/{arc_demo,
  circle_demo, figure8_demo, helix_demo, pick_place_single_rnea, pick_place_single,
  pick_place_single_wait}`. Regenerate with `make MODEL=<name> codegen DIR=<out>`;
  diff `ref_main.cpp`, `introspection_runtime.hpp`, `introspect_model.hpp`,
  `headers/runtime.hpp`. **Excluded (pre-existing breakage, not this refactor):**
  `pick_place_dual` fails SHACL (duplicate `mj:trace-target`) and
  `pick_place_relative` fails DSL parse at line 128 — both die before codegen.
  Env: `source .venv/bin/activate`, `export METAMODELS_PATH=$PWD/src/metamodels`,
  `stst` on PATH.
- Follow-up worth doing after all six land: a CI grep guard that fails if
  `ir_gen.py` reintroduces `KDL::` / `shared.` / `<type> &<name>` C++ strings.
